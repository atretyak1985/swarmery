# API конфігурації проєкту

Два маршрути стоять за модальним вікном **налаштувати** плагіна: вони пишуть оверлей
`.claude/project.json` проєкту й допомагають його заповнити. Обидва ключовані *оголошеним*
ключем конфігурації — пакет заявляє, який ключ верхнього рівня йому потрібен, у
`plugins/<pack>/requirements.json` (`EXTENDING.md` → «Pack requirements»). Демон ніколи не
дізнається, що ключ означає: пакети оголошують, `internal/pluginreq` оцінює, а ці
обробники лише огороджують.

## Огорожа

Однакова на обох маршрутах і скопійована із запису перемикача плагінів, а не спрощена —
проба нічого не пише, але породжує процес із текою проєкту як cwd, і це не привід
огороджувати її слабше:

1. **Лише локальне походження** — `requireLocalOrigin` обгортає обидва маршрути
   (`internal/api/routes.go`).
2. **Корені підключення мають бути задані** — порожній `SWARMERY_ONBOARD_ROOTS` вимикає
   обидва: `403`.
3. **Шлях має розв’язуватися під цими коренями** — `resolveUnderRoots` на шляху з рядка
   `projects`; усе поза ними — `403`.

Ще дві перевірки належать самим ендпоінтам: ключ має бути таким, що його **оголосив**
каталогізований пакет (`404 unknown config key`), і — лише на записі — значення має
задовольняти фрагмент схеми цього пакета (`422`). Без першої маршрут стає довільним
писарем будь-якого ключа в будь-який `project.json`.

## `PUT /api/projects/{id}/config/{key}`

Пише рівно один ключ верхнього рівня. Тіло — `value` має бути JSON-об’єктом; скаляр або
`null` — це `400`:

```json
{ "value": { "…": "the whole block for this key" } }
```

`200`:

```json
{ "key": "jira", "written": true, "backup": ".claude/project.json.bak", "changed": true }
```

`changed` дорівнює `false`, коли ключ уже тримав саме це значення; запис усе одно відбувся,
тож UI може сказати «без змін» замість заявляти про збереження, яке нічого не зрушило.

`422` несе проблеми по кожному полю, щоб модальне вікно могло поставити кожну поруч із її
полем вводу:

```json
{ "error": "jira does not satisfy the schema declared for it", "problems": ["…"] }
```

Інші відмови: `400` — неправильний id або тіло, `404` — маркетплейс не встановлено /
неоголошений ключ, `409` — не керований оверлей (немає `.claude/project.json`) або наявний
файл не парситься.

**Інваріант — злиття одного ключа, спершу резервна копія.** Наявний файл декодується,
замінюється лише `key`, і він кодується знову: кожен чужий ключ, його порядок і
форматування файлу зберігаються. Попередній вміст записується у `<file>.bak` *перш ніж*
новий файл атомарно стане на місце. `.bak` лягає поруч зі **справжнім** файлом, який для
оверлея через symlink лежить не в теці проєкту, — `backup` у відповіді каже, де шукати.

## `POST /api/projects/{id}/config/{key}/probe`

Пропонує живі значення для полів, які блок `probe` пакета номінував, передаючи промпт
пакета сесії `claude`, що вже несе конектори оператора. **Вона нічого не пише**, а демон
не отримує ані клієнта, ані токена. Тіло — поточний частковий вміст форми:

```json
{ "value": { "…": "partial config" } }
```

`200` — успіх і невдача мають одну форму, тож у браузера одна гілка коду:

```json
{ "suggestions": { "qaStatus": ["…"] }, "reason": "", "notes": "" }
```

`suggestions` — це «шлях поля через крапку → кандидати», ніколи не `null`, обмежені
білим списком `fields`, які номінував пакет. `reason` задається лише тоді, коли нічого не
повернулося.

**Інваріант — проба ніколи не падає з 5xx.** Тайм-аут, відсутній бінарник `claude`,
процес, що впав, проза замість JSON, конектор, що не розв’язався, — кожен випадок це
`200` з порожніми `suggestions` і однорядковим `reason`. Червона 500 над необов’язковою
зручністю навчила б оператора, що сторінка конфігурації зламана; форма ж працює і без
цієї допомоги. 5xx тут недосяжна навмисно.

Три відмови все ж передують будь-якому запуску агента: огорожа вище, `404`, коли ключ не
оголошує `probe` (UI пропонує кнопку лише тоді, коли він є, тож дійти сюди — баг), і
`400`, коли вхідні дані `needs` проби ще не заповнені — єдиний збій, який оператор може
виправити у формі, на яку вже дивиться, і який не вартий трьох хвилин часу агента на
звіт.
