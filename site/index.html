control plane

One binary that watches the whole swarm.

A single Go daemon with an embedded React dashboard. It reads the session transcripts Claude Code already writes, indexes them into local SQLite, and serves everything on one port that never leaves the loopback interface. Nothing to install in your projects.

  • Sessions you already ran show up at once
  • Approvals reach your phone, so a waiting run is unblocked away from the desk
  • launchd on macOS, systemd on Linux

why it holds together

Six rules, each enforced by something you can run.

A scan, a gate, a worktree, a verdict. None of them is a convention you have to remember.

neutrality

A core that names no one

Brand tokens are forbidden anywhere under plugins/, and a CI ratchet keeps the count at zero. Each project's flavor arrives at runtime from its own project.json.

graduation

Flow goes up only

A component is born project-local, moves to a domain pack when a second project needs it, and reaches the core only when every project does. Nothing is copied downward.

isolation

One worktree per run

Every phase run and every dispatched task gets its own branch in an isolated git worktree. Your working tree is never the agent's workspace.

verification

Verdicts that can say no

A read-only verifier diffs the work against the persisted start point and returns PASS, FAIL or INCONCLUSIVE. Done means the criteria are ticked and the report is written, not that a process exited 0.

plans

A phase graph, not a wish list

Every phase carries measurable acceptance criteria, a forecast and a completion report. Runs execute the graph in dependency order, and the markdown on disk stays the source of truth.

observability

Everything on the record

Every session transcript is indexed into local SQLite: tokens, cost, approvals, forecasts against actuals, and the lessons drawn from the gap. Nothing leaves the machine.
