plugin marketplace

One core, opt-in packs.

A Claude Code plugin marketplace: the core carries everything that is true for every project, and domain packs add the vocabulary and tooling of one kind of work. A project enables only what it uses, and its own flavor arrives at runtime from .claude/project.json.

/plugin marketplace add atretyak1985/swarmery

core@swarmery

The vendor-neutral core.

Vendor-neutral agent-development core: generic agents, skills, commands, hooks, and the project-aware agent-work CLI.

/plugin install core@swarmery

Infrastructure & delivery domain pack: Kubernetes/Helm, GitOps promotion, IaC, GitLab CI, cloud CI auth (GCP + AWS), Keycloak. Opt-in; requires core.

/plugin install infra-pack@swarmery

Semantic code-navigation pack: Serena LSP MCP server. Opt-in; requires the serena binary (uv) on the machine.

/plugin install lsp-pack@swarmery
claude-eng-packagent engineering

Claude-engineering pack: skills for building/auditing Claude agent systems — agent architecture, tool/MCP design, prompt engineering, Claude Code config, context reliability. Opt-in; requires core.

/plugin install claude-eng-pack@swarmery
graft-packcode intelligence

Context-graph pack: the graft skill plus two hooks — coverage-gated file:line locators injected into a prompt before the first grep, and a blast-radius note after every edit. Opt-in; requires the graft CLI on the machine.

/plugin install graft-pack@swarmery
graphify-packcode intelligence

Knowledge-graph pack: the /graphify skill — repo/folder → persistent knowledge graph with query/path/affected tools and HTML/JSON/Neo4j exports. Opt-in; requires the graphify CLI on the machine.

/plugin install graphify-pack@swarmery
architecture-packcode intelligence

Repo-wide architecture map: /architecture-map generates a machine-readable JSON contract (layers, modules, file-anchored flows) + self-contained HTML viewer, freshness-stamped per commit; the swarmery dashboard serves both on its Architecture page. Also /visualize: turn a document or an explanation into one interactive, self-contained HTML explainer page.

/plugin install architecture-pack@swarmery
jira-packworkflow

Issue-tracker pack: /jira-fix drives any Jira ticket end-to-end — access preflight, defect-or-change triage, reproduction or test-first evidence, delegated fix/implementation, evidence comment, QA transition. Opt-in; requires core and an Atlassian MCP provider enabled on the machine.

/plugin install jira-pack@swarmery
accounts-packworkflow

Multi-account pack: bind a project to one of several Claude Code accounts and run every session under it — /account, a shell wrapper, an optional shell function, and a wrong-account warning. The binding is machine-local, and a binding file committed to git is ignored. Opt-in; requires the swarmery CLI.

/plugin install accounts-pack@swarmery
design-packworkflow

Design-handoff pack: /design-implement takes an exported design and re-expresses it in the project's stack pixel-accurately — computed-style token inventory, reuse-vs-create recon, an approval gate, and a measured pixel diff as the completion criterion. Opt-in; requires core.

/plugin install design-pack@swarmery
review-packworkflow

Pull-request review pack: /pr-review reviews a GitHub PR and posts verified inline findings, or triages the reviewer comments on it — verify each against the code, fix the valid ones behind the repo's gates, rebut the rest with file:line evidence, reply in-thread. Opt-in; requires the gh CLI.

/plugin install review-pack@swarmery

graduation

Flow goes up only.

How a component ends up in a pack, and why nothing is ever copied back down into a project.

1 · born local

In one project's .claude/

New agents and skills start where they are needed. A project-local component overrides the plugin's on a name collision: that is the override mechanism, not a fork.

2 · a second project

Promoted to a domain pack

De-flavored, moved into the pack, the pack's version bumped, and the donor's local copy deleted.

3 · every project

Promoted to the core

Only when every project needs it. A neutrality scan keeps brand names out of plugins/, and the count stays at zero.
