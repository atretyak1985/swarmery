# Робочий процес агентів

`core` у swarmery — не один чатбот, а **оркестрований флот**. `@tech-lead` —
агент, якого ви викликаєте напряму; він розбирається в задачі, виносить на поверхню
питання, на які можете відповісти лише ви, маршрутизує роботу виконавцям, дібраним
за розміром задачі, гейтує результат незалежним рев’ю і закриває підсумком у вашому
workspace. Саме це показує вам **Хронологія** сесії в центрі керування: делегування,
вердикти рев’ю і виклики інструментів кожного делегата.

Із core 3.0 флот — це **13 агентів-суддів** (замість 42 машин-правил);
роль кожного агента — сторінка, а не збірник правил, а «як» живе в скілах, що
розкриваються поступово. Мапа старе→нове — у `plugins/core/AGENTS.md`.

## Маршрутизація за розміром (судження, а не церемонія)

| Форма задачі | Маршрут |
|---|---|
| **Баг** | `@debugger` знаходить корінь ПЕРШ НІЖ хтось планує виправлення |
| **Мала** — один файл, добре зрозуміла | `@implementation-agent` з одним сфокусованим брифом |
| **Середня** — кілька файлів, потрібна послідовність | `@planner` пише короткий план → 2–3 виконавці його виконують |
| **Велика** — кілька репозиторіїв, зміни схем | `@architect` спершу проєктує; вбудована оркестрація динамічних робочих процесів для розгалуження на весь кодбейс |

Кожен маршрут закінчується однаково: незалежний прохід **`@code-reviewer`** без права на запис
по диффу перед комітом (плюс `@security-auditor`, коли зміна торкається автентифікації, обробки
вводу, секретів чи інфраструктури), далі — закривальні артефакти через скіл `session-closeout`.

## Флот (13)

| Агент | Клас | Що робить |
|---|---|---|
| `@tech-lead` | оркестратор | маршрутизує, делегує, гейтує, закриває |
| `@planner` | планування | плани workspace: документи фаз, критерії, промпти виконавців |
| `@architect` | дизайн | дизайн системи/API/даних, безпека міграцій, розкочування |
| `@researcher` | лише читання | оцінка технологій, аналіз впливу, синтез контексту |
| `@implementation-agent` | виконавець | виконання коду (лист) або оркестрація виконання плану |
| `@ui-developer` | виконавець | фронтенд із гейтами типів/токенів/a11y/стану |
| `@debugger` | виконавець | спершу корінь проблеми, мінімальне доведене виправлення |
| `@test-writer` | виконавець | тести, що фіксують поведінку |
| `@test-runner` | лише читання | запускає набори тестів, звітує точно |
| `@code-reviewer` | лише читання | багатолінзове рев’ю, рядок `VERDICT:` |
| `@security-auditor` | лише читання | OWASP + STRIDE зі шляхами атак |
| `@verification-agent` | лише читання | детерміновані перевірки (build/type/lint/test) |
| `@system-improver` | мета | діагноз усієї системи з посиланнями на докази |

Агенти лише для читання несуть списки дозволених `tools:` без Edit/Write. Агенти, що видають
вердикт, закінчують машинною граматикою `VERDICT: PASS | FAIL | INCONCLUSIVE` — тим самим рядком,
який розбирає рушій перевірки центру керування.

## Рівні моделей (драбина вартості)

Кожен агент працює на найдешевшому рівні, який йому підходить — це видно на вкладці **Здоров’я → Вартість і токени** дашборду
і в заголовку вартості кожної сесії. Моделі — завжди псевдоніми (`opus`/`sonnet`/`haiku`), тож
ротації моделей ніколи не лишають флот без моделі.

| Рівень | Модель | Роль |
|---|---|---|
| **T0/T1** | Opus | оркестрація, планування, дизайн, судження в рев’ю |
| **T2** | Sonnet | стандарт флоту — виконання, налагодження, дослідження |
| **T3** | Haiku | швидкі механічні перевірки і звітування |

## Гейти з людиною в контурі

Робочий процес зупиняється заради вас — це видно у **Вхідних** центру керування —
перед: git-комітами/пушами · міграціями бази даних · несумісними змінами API ·
змінами, чутливими до безпеки · розгортаннями у production. Ризиковані дії отримують структуроване
«так/ні» від скіла `guardrails` (Вплив × Зворотність; Critical ніколи не
погоджується автоматично). Автономні запуски розв’язують питання, що потребують лише користувача, ПЕРШ НІЖ почнеться розгалуження.
Ці гейти завжди чекають на вас: агент-сортувальник може позначати здогади класифікатора і
закривати суто інформаційні елементи з Вхідних (можна скасувати протягом семи днів), але він ніколи
не відповідає на погодження, зміну агента чи сповіщення. **Запустити сортування** у Вхідних стартує запуск
рівно над тими елементами, які рахує стрічка — здогадами класифікатора, знахідками радника,
кандидатами в уроки і списаннями — і ніколи над групами тертя чи агентами зі Здоров’я; один
запуск відвідує щонайбільше 1000 елементів. Здоров’я → Тертя має власне **запустити сортування** для повторюваних груп
помилок і агентів, що падають, тож два тригери ділять роботу; нічна рутина
позначає лише здогади класифікатора.

## Де це живе

`@tech-lead` і кожен делегат постачаються в `core` — увімкніть його, і робочий процес
доступний у будь-якому проєкті. Локальні агенти проєкту з тим самим ім’ям перекривають агентів
core (див. [розширення](extending)); флейвор для кожного проєкту береться з `project.json` (див.
[нейтральність](neutrality)).
